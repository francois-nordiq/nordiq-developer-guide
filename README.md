# Nordiq Developer Guide

The developer guide for the Nordiq Agentic System — architecture, the data
model, the five repos, and how AI subagents are used to build them. Built
with [Docusaurus](https://docusaurus.io/).

Content source: [`docs/`](./docs). Start at
[`docs/intro.md`](./docs/intro.md).

## Local development

```bash
npm install
npm start
```

Starts a local dev server at `http://localhost:3000/nordiq-developer-guide/`
with live reload.

## Build

```bash
npm run build
```

Generates static content into `build/`. Verify a production build locally
before pushing:

```bash
npm run build && npm run serve
```

## Publishing to GitHub Pages

This repo is set up two ways — pick one.

### Option A: GitHub Actions (recommended, already wired up)

[`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml) builds and
deploys on every push to `main`. One-time setup after the repo exists on
GitHub:

1. Repo **Settings → Pages → Source** → select **GitHub Actions**.
2. Push to `main`. The site publishes to
   `https://francois-nordiq.github.io/nordiq-developer-guide/`.

### Option B: `npm run deploy` (manual, from your machine)

```bash
GIT_USER=<your-github-username> npm run deploy   # HTTPS
USE_SSH=true npm run deploy                       # SSH
```

Builds and pushes straight to the `gh-pages` branch. Useful for a one-off
publish before CI is wired up, but Option A is the source of truth going
forward — don't run both against the same repo without keeping them in
sync.

## Content structure

```
docs/
├── intro.md
├── architecture/       # the agent loop, platform conventions, data model, event bus
├── repos/               # the five repos + dependency graph
├── ai-agent-context/     # the Chief Architect / subagent development model
└── examples/             # worked examples tying the conventions together
```

Sidebar order is manually curated in [`sidebars.ts`](./sidebars.ts) rather
than autogenerated, so it reads top-to-bottom the way a new contributor
should encounter it.

## Keeping this in sync with the workspace

This guide's content is sourced from the `CLAUDE.md` files and
`.claude/agents/*.md` subagent definitions across the Nordiq workspace
repos. When those change — a new architectural pattern, a new subagent, a
repo's stack getting filled in — update the corresponding page here in the
same change, the same way a schema change updates its consumers.
